# 微信小程序全栈从 0 到 1 开发提示词（可复用）

> **用途**：本提示词沉淀了「农家产品销售展示平台」项目从 0 到 1 跑通「unibest 前端 + Next.js 后端 + PostgreSQL 数据库 + 微信小程序」的完整流程与全部踩坑经验。下次开发新的微信小程序时，可直接复制本提示词交给 AI 助手（或人工照做），按「标准流程」执行即可跑通，并主动规避「踩坑清单」中的问题。
>
> **适用范围**：unibest 模板（uniapp + Vue3 + TS + Vite5 + UnoCSS + wot-ui）前端 + Next.js 15 + Prisma + PostgreSQL 后端，输出 H5 与微信小程序双端。
>
> **最后验证时间**：2026-08-04（H5 全流程 + 小程序首页均实测通过）

## 一、整体架构与版本基线

| 端     | 技术栈                                                       | 版本/说明                                                                   |
| ------ | ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 前端   | unibest 模板（uniapp + Vue3 + TS + Vite5 + UnoCSS + wot-ui） | vite 5.2.8，编译器 4.76，wot-ui 2.3.0                                       |
| 后端   | Next.js 15 + Prisma + PostgreSQL                             | Next.js 15.5.22，Prisma ORM，数据库 farm_db                                 |
| 包管理 | pnpm                                                         | **frontend 目录 corepack 自动切 pnpm 10.10.0；backend 用全局 pnpm 11.18.0** |
| 工具   | 微信开发者工具                                               | CLI 路径：`D:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat`        |

**环境变量关键项（frontend/env/.env）**：

- `VITE_APP_PROXY_PREFIX = '/api'`：H5 代理前缀（后端业务 API 自带 /api，见坑 4）
- `VITE_SERVER_BASEURL__WEIXIN_DEVELOP = 'http://localhost:3000'`：小程序端专用后端地址
- `VITE_WX_APPID`：小程序 AppID（manifest.config.ts 自动同步）
- `WECHAT_DEVTOOLS_CLI_PATH`：微信开发者工具 CLI 路径（非默认安装位置必须配）

## 二、从 0 到 1 标准流程

### 阶段 0：前置环境检查（约 5 分钟）

1. 确认 Node.js ≥ 18、pnpm ≥ 10 已安装
2. 确认 PostgreSQL 已启动，可用 `psql` 或 pgAdmin 建库：`CREATE DATABASE 项目名_db;`
3. 确认微信开发者工具已安装并**登录微信**（未装：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html）
4. ⚠️ 若项目目录是从别处**复制/移动**过来的（如 `D:\vue\my-project` → `D:\my-project`），必须先处理 node_modules 链接损坏（见坑 1），再进入阶段 1

### 阶段 1：创建前端项目（unibest 模板）

```bash
# 方式一：官方脚手架（推荐）
pnpm create unibest@latest        # 交互式选择项目名
# 方式二：模板仓库克隆
git clone https://github.com/unibest-tech/unibest.git 项目名
```

创建后：

1. **配置环境变量**（frontend/env/.env）：改 `VITE_APP_TITLE`、`VITE_WX_APPID`（用户真实 AppID）、`VITE_SERVER_BASEURL`/`VITE_SERVER_BASEURL__WEIXIN_DEVELOP` 指向后端地址
2. **配置 pnpm 构建白名单**（见坑 2，不配会启动报 `Cannot find module '@dcloudio/vite-plugin-uni/bin/uni.js'` 或依赖构建脚本不执行）：
   - frontend/pnpm-workspace.yaml（pnpm 10 格式）：
     ```yaml
     onlyBuiltDependencies:
       - esbuild
       - "@swc/core"
       - sharp
       - sass
       - less
       - core-js
       - es5-ext
       - protobufjs
       - vue-demi
       - "@uni-helper/unocss-preset-uni"
     overrides:
       unconfig: 7.3.2
       bin-wrapper: npm:bin-wrapper-china
     ```
   - backend/pnpm-workspace.yaml（pnpm 11 格式）：
     ```yaml
     allowBuilds:
       "@prisma/client": true
       "@prisma/engines": true
       prisma: true
       sharp: true
       bcrypt: true
       esbuild: true
       "@swc/core": true
       unrs-resolver: true
     ```
3. **安装依赖**：`pnpm install`（若前面阶段 0 检测到 junction 损坏，先删除 node_modules 再装）
4. **验证**：`pnpm dev:h5` 能启动（默认 8060 端口）

### 阶段 2：搭建后端（Next.js + Prisma + PostgreSQL）

```bash
mkdir backend && cd backend
pnpm init
pnpm add next@15 react react-dom prisma @prisma/client bcryptjs jsonwebtoken
pnpm add -D typescript @types/node @types/react @types/react-dom @types/bcryptjs @types/jsonwebtoken
```

关键步骤：

1. `prisma init` → 编辑 `prisma/schema.prisma`（User/Product/Order 三模型 + 枚举，注意 `origin`、`unit`、`images String[]` 等字段与前端类型一一对应）
2. `prisma migrate dev --name init`（自动建表）
3. `prisma db seed` 或脚本灌入测试数据（**写中文数据必须用 Node/UTF-8 方式，别用 PowerShell 5.1 发 JSON，见坑 7**）
4. 统一响应格式：`{ code, message, data }`；JWT 7 天有效期；登录/注册/me/logout + 产品 CRUD + /api/upload 上传
5. **next.config.js 给 /uploads 静态资源加 CORS 头**（见坑 6）：
   ```js
   { source: '/uploads/:path*', headers: [
     { key: 'Access-Control-Allow-Origin', value: '*' },
     { key: 'Access-Control-Allow-Methods', value: 'GET,OPTIONS' },
   ]}
   ```
6. 验证：`pnpm dev` 启动后逐个接口实测（注册→登录→升级卖家→发布→列表→me→无 token 401）

### 阶段 3：前后端联调（H5 先行）

1. 启动后端 `pnpm dev`（backend，3000）+ 前端 `pnpm dev:h5`（frontend，8060）
2. 浏览器走通：首页产品 → 登录 → 个人中心（角色标签/我的发布）→ 发布（图片上传）→ 首页/列表/详情
3. 重点检查：网络请求 URL（是否有双前缀）、控制台报错、上传图片是否可显示
4. ⚠️ 修改 `src/http/interceptor.ts` 等启动期代码后**必须整页刷新/重启**，HMR 不生效（见坑 5）

### 阶段 4：微信小程序端联调

1. 启动小程序编译：`pnpm dev:mp-weixin`（产物 `dist/dev/mp-weixin`，watch 模式）
2. 首次配置微信开发者工具：
   - 打开工具 → **设置 → 安全设置 → 服务端口：开启**（CLI 调用必须，见坑 10）
   - 若工具非默认安装路径，env/.env 配 `WECHAT_DEVTOOLS_CLI_PATH`
3. 两种打开方式：
   - 自动：重新跑 `pnpm dev:mp-weixin`，编译完自动拉起工具打开项目
   - 手动：工具 → 导入项目 → 目录选 `dist/dev/mp-weixin` → AppID 选测试号或自己的
4. 工具内验证：首页 → 登录 → 发布（小程序走 uni.uploadFile）→ 详情页；**Console 无报错即通过**
5. 图片 URL：小程序端 `resolveAssetUrl` 自动拼 `VITE_SERVER_BASEURL__WEIXIN_DEVELOP`（见"可复用经验"第 1 条）
6. 真机预览注意：`localhost:3000` 在手机上指向手机自身，需把 env 改成局域网 IP 再重新编译

## 三、踩坑清单与规避方案（重点）

| #   | 现象                                                               | 根因                                                                                                                                                                                                                                                                                                             | 规避方法                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 启动报 `Cannot find module '@dcloudio/vite-plugin-uni/bin/uni.js'` | 项目目录复制/迁移后，node_modules 中 junction 全部指向旧路径（本项目 1736 个指向 `D:\vue\my-project`）                                                                                                                                                                                                           | 删除整个 node_modules 重装；检测脚本注意 `$item.Target` 是 String[]，需 `-join ' '` 判断，Test-Path 对坏链接仍返回 True，不能用来检测                                                                 |
| 2   | pnpm 安装后依赖缺失/构建脚本不执行                                 | corepack 按 package.json `packageManager` 字段自动切换 pnpm 版本（本项目 frontend=10.10.0，backend=11.18.0）；**pnpm 10 用 `onlyBuiltDependencies`（列表），pnpm 11 用 `allowBuilds`（映射）**，且配置位置在 pnpm-workspace.yaml（不是 package.json 的 pnpm 字段）                                               | 先 `pnpm --version` 确认实际版本，再按对应格式写 pnpm-workspace.yaml；装完执行 `pnpm rebuild` 补跑构建脚本                                                                                            |
| 3   | 请求 404，URL 变成 `/api/api/products`                             | unibest 拦截器在 H5 代理开启时自动拼 `VITE_APP_PROXY_PREFIX`（/api），而业务 API 路径自身已带 /api                                                                                                                                                                                                               | interceptor.ts 中判断：`if (!options.url.startsWith(import.meta.env.VITE_APP_PROXY_PREFIX))` 再拼接；**注意写 `` `/${PREFIX}` `` 会生成 `//api`（双斜杠）导致判断永远失效，必须用 `PREFIX` 直接比较** |
| 4   | 改拦截器/请求封装后不生效                                          | `uni.addInterceptor` 只在应用启动时安装，HMR 不会重跑                                                                                                                                                                                                                                                            | 修改后整页刷新或重启 dev server；调试时优先看 Network 实际请求 URL 定位                                                                                                                               |
| 5   | 页面报组件不存在 / 组件 warn                                       | wot-ui 2.x 组件名与 API 与 1.x 不同：`wd-uploader` 不存在（是 `wd-upload`）；`wd-upload` 不支持 v-model（用 `v-model:file-list` + `:action` + `@change`）；上传成功信息在 `file.response`（字符串需 JSON.parse）；`wd-picker` 的 modelValue 期望**数组**；`wd-input` 的 type 不支持 textarea（用 `wd-textarea`） | 写页面组件前先查 wot-ui 文档或 node_modules 里组件 types 定义；`v-model:xxx` 报 "Extraneous non-props attributes" 即 v-model 用法不对                                                                 |
| 6   | 图片跨域/无法显示                                                  | Next.js public 静态资源默认无 CORS 头（<image> 标签不受限，fetch 会拦截）                                                                                                                                                                                                                                        | next.config.js 给 /uploads/:path* 加 Access-Control-Allow-Origin: *                                                                                                                                   |
| 7   | 测试数据中文变 `?` 乱码                                            | PowerShell 5.1 发送中文 JSON 编码问题                                                                                                                                                                                                                                                                            | 写 Node 脚本（原生 fetch，UTF-8）修复/灌入数据                                                                                                                                                        |
| 8   | 浏览器上传产生 8 字节损坏图片                                      | 异常中断的上传                                                                                                                                                                                                                                                                                                   | 定期检查 public/uploads 下文件大小异常（<100B）的删掉，用有效图替换引用                                                                                                                               |
| 9   | CLI 打开工具报 `IDE service port disabled`                         | 微信开发者工具服务端口未开启（安全机制）                                                                                                                                                                                                                                                                         | 工具内：设置 → 安全设置 → 服务端口开启；开启后重启工具也保持                                                                                                                                          |
| 10  | 工具自动打开失败 `系统找不到指定的路径`                            | 工具安装位置非默认（脚本默认找 `C:\Program Files (x86)\Tencent\微信web开发者工具`）                                                                                                                                                                                                                              | env/.env 配置 `WECHAT_DEVTOOLS_CLI_PATH = '实际路径\cli.bat'`                                                                                                                                         |
| 11  | 改 AppID 不生效                                                    | manifest.json 里的 appid 是硬编码模板值                                                                                                                                                                                                                                                                          | 统一改 env/.env 的 `VITE_WX_APPID`，manifest.config.ts 会自动同步（mp-weixin.appid = VITE_WX_APPID），watch 编译自动重新生成 project.config.json                                                      |
| 12  | 终端/服务进程被清理                                                | IDE 重启、长时间未操作等导致 dev server 停止                                                                                                                                                                                                                                                                     | 记住重启命令：backend `pnpm dev`（3000）、frontend H5 `pnpm dev:h5`（8060）、小程序 `pnpm dev:mp-weixin`；重启后检查端口存活                                                                          |
| 13  | 请求 `http://localhost` 被拒                                       | 小程序未关合法域名校验                                                                                                                                                                                                                                                                                           | manifest.config.ts `mp-weixin.setting.urlCheck: false`（开发期），上线前改 true 并配 https 域名                                                                                                       |

## 四、可复用经验（做对了的部分）

1. **图片 URL 双端处理**：`src/utils/request.ts` 的 `resolveAssetUrl()` —— H5/小程序统一把 `/uploads/xxx` 拼成完整地址（小程序用 `VITE_SERVER_BASEURL__WEIXIN_DEVELOP`），所有页面统一用它渲染图片，避免平台差异
2. **manifest.config.ts 集中管理端配置**：AppID、urlCheck、导航栏、分包优化等全部走环境变量 + 单一配置文件，改配置不用改 manifest.json
3. **拦截器统一鉴权**：请求自动带 token、401 自动跳登录，业务代码零侵入
4. **分步执行规范**：每个阶段完成 → 更新 md 进度标记 → 汇报 → 用户决策下一步，避免一次性大改造成问题难定位
5. **后端统一响应 `{code, message, data}`**：前后端联调时解析逻辑简单一致，上传接口返回 `{code:0, data:{url}}` 与 wd-upload 解析逻辑匹配

## 五、新项目跑通检查清单（开箱自检）

- [ ] 阶段 0：目录无历史 junction 残留（复制来的项目先删 node_modules）
- [ ] `pnpm install` 成功且 `pnpm --version` 与 package.json 的 packageManager 一致
- [ ] `pnpm rebuild` 无构建脚本报错（esbuild/swc/sharp/prisma 等）
- [ ] `pnpm dev:h5` 启动无红字，`pnpm dev:mp-weixin` 编译 DONE
- [ ] 后端接口全绿：注册/登录/me 鉴权/无 token 401/产品 CRUD/上传
- [ ] 微信开发者工具：服务端口已开启、CLI 路径已配置、urlCheck 关闭
- [ ] H5 + 小程序双端：首页 → 登录 → 发布（含图片上传）→ 详情页全流程通过，Console 无报错
- [ ] md 文档进度标记已更新
